# LUODA 3.1.1 新功能 PRD

## 1. 背景

3.0.1 仅支持"主控方连接被控方后单线聊天"。"邀请他人只看不操作"与"多方共享聊天"在 v3.0.1 不存在。
3.1.1 在不破坏既有 P2P 会话与中继会话协议的前提下，引入 viewer 角色 + 邀请链接 + 聊天广播。

## 2. 用户故事

### 2.1 邀请观看
- 主控方 A 远程连接被控方 B 已成功。
- A 在会话面板点击"邀请观看"按钮 → 弹出邀请链接（短码）+ 二维码。
- A 把链接发给第三方 C1, C2, …。
- C 点击链接或在 LUODA 主页"加入观看"输入邀请码 → 以 viewer 身份加入会话，仅能观看 B 的屏幕，不能操作键盘 / 鼠标 / 触摸。
- A 可在"参与者列表"对任意 viewer 执行"提升为协作"（升级为可操作）或"请离"。
- A 关闭会话或主动"结束邀请"时，所有邀请链接立刻失效，已加入的 viewer 被中断。

### 2.2 文字聊天（共享）
- A / B / 所有 viewer 共享同一公共聊天面板。
- 任一方发送一条文字 → 所有参与者收到。
- 保留 1:1 私聊入口（点对点不广播），但默认频道为"公共频道"。
- 历史消息保留在内存（不落盘），会话结束即清空。

## 3. 协议扩展

在 hbb_common::rendezvous::proto::Data 末尾追加三条消息（保持枚举 backward 兼容）：

| ID  | 名称              | 字段                                  | 方向           |
|-----|-------------------|---------------------------------------|----------------|
| 30  | InviteToken       | token: String, expires_at: u64        | server → client |
| 31  | JoinAsViewer      | token: String, viewer_id: String      | client → server |
| 32  | ViewerListUpdate  | viewers: Vec<ViewerInfo>              | server → clients |
| 33  | KickViewer        | viewer_id: String                     | host → server  |
| 34  | PromoteViewer     | viewer_id: String                     | host → server  |

ViewerInfo：{ viewer_id: String, display_name: String, joined_at: u64, promoted: bool }

## 4. 角色与会话隔离

- 在 server::Connection 上新增字段 role: SessionRole，枚举 Host / Guest / Viewer。
- viewer 的输入路径（键盘 / 鼠标 / 触摸 / 剪贴板 / 文件传输）在 input_service 入口处直接拒绝，返回 PermissionDenied。
- viewer 不可发起切换屏幕、修改分辨率、重启服务、修改会话配置。
- viewer 可发送 ChatMessage（公共频道），可发送"举手"信号（仅 UI 高亮 host）。

## 5. 邀请链接

- 形如 luoda://join/<12 位短码>，短码本地逆向查询对应 session_id + viewer_token。
- 短码 base32（Crockford）+ 校验位，避免歧义字符。
- TTL 默认 30 分钟，可由 host 在会话面板调整（5 / 15 / 30 / 60 分钟）或"单次使用即删除"。
- 邀请链接不支持直接拼被控端 ID ——短码本身即会话入口，避免泄露被控端身份。

## 6. 安全模型

- viewer 加入须同时满足：短码有效 + 未被撤销 + 未达 max_viewers（默认 8）。
- viewer ID 由服务端生成（uuid v4），host 端显示"参与者列表"。
- 所有 viewer 流量经 same relay / P2P 通道，但 100% view-only。
- host 可一键"清场"：撤销主邀请 + 踢掉所有 viewer。
- viewer 离开/掉线 → 服务端广播 ViewerListUpdate。

## 8. 不在 3.1.1 范围

- viewer 端录制 / 截屏（防泄漏，3.2 再做）。
- 跨会话邀请链接转交（防止滥用）。
- viewer 端文件传输（默认拒绝）。
- 邀请人付费墙 / 用量统计（产品侧后续接入）。

## 9. 验收

- 主控可生成有效邀请链接，复制后可在另一台机器 1 分钟内成功加入观看。
- viewer 无任何键盘 / 鼠标 / 文件操作权限。
- 任意一方发送聊天消息 → 所有参与者 1 秒内可见。
- Host 一键"清场" → 所有 viewer 立即断开。
- 邀请链接过期或被撤销 → viewer 无法再以此加入。
- 老版本 peer（3.0.1）连接 3.1.1 server 不受影响（未知枚举被忽略）。
- 3.0.1 client 连接 3.1.1 server：依然以原 Host/Guest 身份工作，不感知新功能。

## 12. Flutter UI 4 个组件的落地契约

下列 4 个 widget 必须在线上 Flutter 构建环境（flutter pub get + flutter_rust_bridge_codegen 可执行的环境）下落地，本会话只产出 contract，不生成 dart 代码：

1. **Host 主动邀请观看对话框** lib/desktop/widgets/invite_viewer_dialog.dart

   - 动作：调用 session_request_invite_token(sessionId, ttlMinutes: int, oneShot: bool) → session_invite_token_stream 监听 InviteToken 消息 → 展示 12 位短码 + 二维码。
   - 二维码编码内容：luoda://join/<short_code>
   - 提交：
navigator.pop() 返回字串 "<short_code>" 供调用方拷贝；FFI 入口 session_send_chat_to_viewer / session_kick_viewer / session_promote_viewer / session_raise_hand 均已在 src/flutter_ffi.rs:724 暴露。
2. **客户端「加入观看」输入框** lib/common/widgets/join_viewer_page.dart
   - 提交：session_join_as_viewer(sessionId, token: <rawShortCode>, viewerId: <generateUuidV4()>, displayName: <whoami::fallible::get_username() || 'viewer'>) 通过 Misc::JoinAsViewer 上送；服务端 connection.rs::handle_join_as_viewer 解析短码 → 命中会话 → 注入 viewer 注册表。
3. **会话内参与者列表 widget** lib/common/widgets/viewer_list_panel.dart
   - 输入：监听 viewer_list_update_stream（由 Misc::ViewerListUpdate 反序列化而来，已在 io_loop.rs:1908 Misc 分支解析）

调用方约定：以上 4 个 widget 全部通过既有 frb 桥（PlatformFFI）调用 Rust 端的方法，无需新增 frb api 表项；只需要在 flutter_ffi.rs 已有的 4 个 viewer-control 入口（session_send_chat_to_viewer / session_kick_viewer / session_promote_viewer / session_raise_hand）以及 session_request_invite_token / session_join_as_viewer（已 land 的 3.1.1 服务端入口，见 src/flutter_ffi.rs）上接出即可。
